# 智能 RTSP 地址获取 - 快速开始指南

## 🚀 5 分钟快速上手

### 步骤 1：添加网络摄像机

1. 点击 **"添加信号源"** 按钮
2. 选择类型：**网络摄像机**
3. 选择协议：**ONVIF**（推荐）或 **RTSP**

---

### 步骤 2：填写基本信息

#### 方案 A：ONVIF 协议（自动获取，推荐）

```
IP 地址: 192.168.5.165
ONVIF 端口: 2000（常见值：80, 8000, 8080, 8899）
用户名: admin
密码: admin
摄像头品牌: [可选] 选择对应品牌可提高成功率
```

点击 **"自动获取RTSP地址"** 按钮，系统会自动尝试获取。

---

#### 方案 B：RTSP 协议（手动指定）

```
流媒体地址: rtsp://192.168.5.165:554/live/av0
需要认证: ☑️
用户名: admin
密码: admin
```

如果不确定地址格式，点击下方的 **"常用格式"** 按钮选择对应品牌。

---

### 步骤 3：测试连接

点击 **"确定"** 后，系统会：

1. ✅ 尝试 ONVIF 协议获取地址
2. ✅ 如果失败，智能验证多个 RTSP 模板
3. ✅ 启动 ZLMediaKit 代理服务
4. ✅ 在预览窗口播放视频

---

## 🔍 故障排查

### 问题 1：ONVIF 返回 404 错误

**症状**：

```
ONVIF端口 2000 失败: HTTP 404 - 所有 GetProfiles 路径均失败
```

**解决方案**：

1. **尝试其他端口**：
   - 80, 8000, 8080, 8899, 2000

2. **改用 RTSP 协议**：
   - 选择协议为 RTSP
   - 直接输入 RTSP 地址

3. **使用 ODM 工具**：
   - 下载 ONVIF Device Manager
   - 查看准确的 Media Service URL

---

### 问题 2：RTSP 连接失败

**症状**：

```
无法连接到RTSP流，请检查地址和网络连接
```

**解决方案**：

1. **使用 VLC 测试**：

   ```
   打开 VLC → 媒体 → 打开网络串流
   输入 RTSP 地址 → 播放
   ```

2. **检查端口连通性**：

   ```powershell
   Test-NetConnection 192.168.5.165 -Port 554
   ```

3. **确认用户名密码正确**：
   - 某些摄像头需要认证
   - 尝试将认证信息嵌入 URL：

     ```
     rtsp://admin:password@192.168.5.165:554/live/av0
     ```

---

### 问题 3：视频卡顿或延迟高

**解决方案**：

1. **使用子码流**：
   - 海康：`h264/ch1/sub/av_stream`
   - 大华：`subtype=1`

2. **降低分辨率**：
   - 在摄像机 Web 界面调整

3. **启用 RTSP over TCP**：
   - 减少丢包导致的卡顿

---

## 💡 最佳实践

### ✅ 推荐做法

1. **优先使用 ONVIF 协议**
   - 自动获取，准确可靠
   - 支持云台控制

2. **指定摄像头品牌**
   - 提高智能验证成功率
   - 减少尝试时间

3. **记录已验证的地址**
   - 添加到 `VERIFIED_RTSP_URLS`
   - 下次直接使用，零延迟

4. **使用 ODM 工具诊断**
   - 获取准确的配置信息
   - 查看实时 RTSP URL

---

### ❌ 避免的做法

1. **不要盲目尝试所有端口**
   - 先查阅设备手册
   - 或使用 ODM 扫描

2. **不要忘记认证信息**
   - 大部分摄像头需要用户名密码
   - 确保权限足够

3. **不要忽略网络状况**
   - 确保摄像机和应用在同一局域网
   - 检查防火墙设置
