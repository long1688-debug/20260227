# 网络摄像机功能测试指南

## 一、多网卡扫描功能测试

### 1.1 测试步骤

1. **启动应用**
   ```bash
   cd tauri-app
   npm run tauri dev
   ```

2. **打开摄像机发现面板**
   - 在教师窗口中，点击"添加信号源"按钮
   - 选择"网络摄像机"类别
   - 点击"扫描局域网"按钮

3. **选择多网卡扫描模式**
   - 确保选中"🌐 多网卡扫描（推荐）"选项
   - 设置超时时间（建议5秒）
   - 点击"开始扫描"

4. **验证结果**
   - ✅ 应显示检测到的所有网络接口列表
   - ✅ 每个接口显示：名称、IP地址、子网、是否主网卡
   - ✅ 扫描完成后显示发现的摄像机设备
   - ✅ 设备列表包含：IP地址、端口、设备名称、协议类型

### 1.2 预期行为

- **有网络设备时**: 显示发现的摄像机列表
- **无网络设备时**: 显示提示信息"未发现设备，请检查网络连接"
- **网络接口为空时**: 显示警告"未找到有效的网络接口"

### 1.3 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 未发现任何接口 | 防火墙阻止 | 允许应用访问网络 |
| 扫描超时 | 网络延迟高 | 增加超时时间到10-15秒 |
| 设备无法连接 | 认证信息错误 | 检查用户名/密码 |

## 二、RTSP流预览功能测试

### 2.1 测试准备

#### 方法1: 使用真实RTSP摄像机
1. 准备一台支持RTSP的网络摄像机
2. 获取摄像机的RTSP流地址，例如：
   - 海康威视: `rtsp://192.168.1.100:554/h264/ch1/main/av_stream`
   - 大华: `rtsp://192.168.1.101:554/cam/realmonitor?channel=1&subtype=0`
3. 记录摄像机的用户名和密码

#### 方法2: 使用RTSP测试服务器
```bash
# 使用docker运行RTSP测试服务器
docker run -d --name rtsp-test -p 8554:8554 aler9/rtsp-simple-server
```

### 2.2 测试步骤

1. **添加RTSP信号源**
   - 点击"添加信号源"按钮
   - 选择"本地设备" → "网络摄像机"
   - 填写表单：
     ```
     名称: 测试摄像机
     协议类型: RTSP
     流媒体地址: rtsp://192.168.1.100:554/stream
     需要认证: ✓
     用户名: admin
     密码: 123456
     ```
   - 点击"确定"

2. **验证预览区域播放**
   - ✅ 预览区域应显示"正在连接..."状态
   - ✅ 几秒后显示实时视频画面
   - ✅ 右上角显示PTZ控制按钮（如果支持ONVIF）
   - ✅ 无错误提示

3. **测试播放控制**
   - 暂停/播放
   - 调整音量
   - 全屏切换
   - 截图（如果支持）

4. **测试停止清理**
   - 从预览区域移除信号源
   - 验证后端RTSP会话已停止（查看控制台日志）

### 2.3 预期行为

- **成功场景**:
  ```
  [网络摄像机 RTSP] 尝试转换 RTSP 流: rtsp://...
  [网络摄像机 RTSP] 成功转换为 HTTP 流: http://localhost:xxxx/stream.mjpg
  [网络摄像机 RTSP] 播放成功
  ```

- **失败场景**:
  ```
  [网络摄像机 RTSP] 转换失败: ...
  错误提示: RTSP 流需要后端支持...
  ```

### 2.4 调试技巧

#### 查看后端日志
```bash
# Tauri开发模式下，后端日志会输出到终端
cargo run
```

#### 查看前端控制台
- 打开浏览器开发者工具 (F12)
- 切换到Console标签
- 过滤关键词: `[网络摄像机]` 或 `[RTSP]`

#### 检查活跃会话
```javascript
// 在浏览器控制台执行
const { invoke } = await import('@tauri-apps/api/core');
const sessions = await invoke('get_active_rtsp_sessions');
console.log('活跃的RTSP会话:', sessions);
```

### 2.5 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 播放失败 | RTSP地址错误 | 验证地址格式和端口 |
| 认证失败 | 用户名/密码错误 | 检查摄像机认证信息 |
| 连接超时 | 网络不通 | ping测试摄像机IP |
| 黑屏无画面 | FFmpeg解码失败 | 检查后端日志 |
| 画面卡顿 | 网络带宽不足 | 降低码率或使用子码流 |

## 三、综合测试场景

### 3.1 多路RTSP流同时播放

1. 添加3-4个不同的RTSP信号源
2. 验证所有画面同时正常播放
3. 监控系统资源占用（CPU、内存）
4. 验证音频混音正常（如果启用）

### 3.2 网络切换测试

1. 开始播放RTSP流
2. 断开网络连接
3. 验证错误提示显示
4. 恢复网络连接
5. 验证自动重连或手动重试

### 3.3 长时间稳定性测试

1. 连续播放RTSP流30分钟以上
2. 观察是否有内存泄漏
3. 验证画面是否持续流畅
4. 检查后端进程是否正常

## 四、性能基准

### 4.1 单路RTSP流
- **CPU占用**: < 15% (1080p, H.264)
- **内存占用**: ~100MB
- **延迟**: < 2秒

### 4.2 四路RTSP流
- **CPU占用**: < 50% (1080p, H.264)
- **内存占用**: ~400MB
- **延迟**: < 3秒

### 4.3 优化建议
- 使用子码流降低分辨率
- 调整FFmpeg参数优化性能
- 限制同时播放的RTSP流数量

## 五、故障排除

### 5.1 多网卡扫描无结果

```bash
# 1. 检查网络接口
ipconfig /all  # Windows
ifconfig       # Linux/Mac

# 2. 验证防火墙设置
# Windows: 允许应用通过防火墙
# Linux: sudo ufw allow udp

# 3. 测试ONVIF发现
# 使用ONVIF Device Manager工具验证
```

### 5.2 RTSP流无法播放

```bash
# 1. 测试RTSP流可访问性
ffplay rtsp://192.168.1.100:554/stream

# 2. 检查FFmpeg是否安装
ffmpeg -version

# 3. 验证Tauri后端运行
ps aux | grep tauri

# 4. 查看后端日志
tail -f ~/.local/share/tauri-app/logs/*.log
```

### 5.3 画面闪烁或卡顿

1. 降低视频分辨率或帧率
2. 检查网络带宽占用
3. 关闭其他占用GPU的应用
4. 更新显卡驱动
